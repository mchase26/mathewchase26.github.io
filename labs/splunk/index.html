Project Overview

The objective of this lab was to deploy OPNsense as a virtual firewall between an internal LAN network and the internet-facing WAN interface.


This project simulated a small business network where security policies, traffic filtering, and network services must be properly configured and maintained.

Lab Screenshots and Description

Splunk Installation via SSH

Remotely accessed the Ubuntu Splunk server via SSH from the Windows workstation to install and configure Splunk Enterprise for centralized log collection.

Configured Universal Forwarding Port

Enabled TCP port 9997 under Splunk Forwarding and receiving settings to allow forwarders to transmit telemetry to the Splunk instance.

Verify Active Forwarder Connection

Executed splunk list forward-server via PowerShell to confirm the Universal Forwarder has established an active connection to the Splunk indexer at 192.168.10.30:9997.

Universal Forwarder Stanza Confirmation

Customized the inputs.conf file on the Windows endpoint to collect Application, Security, System, and Sysmon logs into Splunk's main index.

Verify Host Connectivity on Splunk Console

Ran an SPL search for host="Win11Host" to confirm continuous log ingestion from the endpoint into Splunk Search & Reporting.

Event Dashboard Creation

Created a custom dashboard in SIEM Visualizing security metrics, including timeline charts for successful vs. failed logins and a bar chart breakdown of top Windows Event IDs.

Failed Login Activity

Intentionally triggering authentication failures on the Windows lock screen to validate login failure tracking.

Confirmation of Failed Logins

Structured a custom Security Operations Dashboard panel in Splunk to display failed login events, target hosts, failure reasons, and source IP details.

Run Powershell as Administrator

Opened Powershell as administrator to trigger an event in Splunk.

Analyzing Event ID 4672

Reviewing Event ID 4672 (Special privileges assigned to new logon) in Splunk to detect elevated administrator login activity on Win11Host.

Generating New User in PowerShell

Executing net user TestUser password /add via PowerShell on the target host to generate local user management log entries.

Splunk Confirmation Code | Account Created

Searching ingested Windows Security logs in Splunk to confirm the capture of Event ID 4720 (A user account was created).

Project Summary

Lessons Learned

  • Installed and configured Splunk Enterprise on an Ubuntu Server to serve as the centralized SIEM platform.
  • Established secure SSH connectivity from the Windows endpoint to remotely manage the Splunk server.
  • Configured the Splunk Universal Forwarder to collect and forward Windows security events.
  • Integrated Microsoft Sysmon to enhance endpoint visibility with detailed process creation and system activity logs.
  • Validated successful log ingestion by monitoring Windows Security and Sysmon events within Splunk.
  • Created custom dashboards to visualize authentication activity and endpoint events. Simulated common attack scenarios, including failed logon attempts and PowerShell execution, to validate detection capabilities.
  • Reinforced the importance of centralized logging, endpoint visibility, and continuous security monitoring within a Security Operations Center (SOC) environment.
  • Improved troubleshooting skills by diagnosing forwarder connectivity, Sysmon configuration, and log collection issues.

Incident Report

Severity: Informational

Status: In Progress

Objective: Deploy and configure Splunk Enterprise as a centralized Security Information and Event Management (SIEM) platform for monitoring Windows security events within the home lab environment.

Current Implementation: Successfully deployed Splunk Enterprise on an Ubuntu Server, configured the Splunk Universal Forwarder on a Windows endpoint, integrated Sysmon for enhanced endpoint telemetry, and validated centralized log collection and basic security event monitoring.

Planned Enhancements: Expand the SIEM environment by introducing additional Windows and Linux endpoints, external attacker systems, Active Directory integration, IDS/IPS log sources, and advanced detection rules to simulate a larger enterprise Security Operations Center (SOC).

Future Objectives: Develop custom dashboards, implement automated alerting, create advanced SPL detection queries, integrate threat intelligence sources, and perform comprehensive incident response investigations using realistic attack scenarios.

Project Status: The SIEM infrastructure is fully operational and serves as the foundation for future security monitoring, detection engineering, and threat hunting capabilities as the lab continues to evolve.
